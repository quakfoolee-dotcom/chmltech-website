    Methodology

    How this database is built and checked.

    Data as of November 12, 2026. 473 benchmark results and 48 list prices, each linked to the page it came from.

    Gather from the source

    Four research agents read each benchmark's own leaderboard or data file and each developer's model and price pages. Every value was copied as published, with the address it came from.

    Use maintainers' results

    Rankings use the results each benchmark publishes on its own board. Scores that developers report about their own models in announcements or model cards are not used. Some boards accept submitted runs; their notes say so.

    Match names carefully

    Benchmarks spell model names differently. Each name is matched to one entry. Earlier snapshots, previews, quantised builds and products not sold through the API are kept apart. When a model appears at several reasoning-effort settings, it is ranked on its best setting, which is shown with the score.

    Red-team before publishing

    Two further agents that did not collect the data re-checked values against the source pages and challenged the name matches, prices, costs and wording. Errors they found are fixed, or the value is removed, before publication.

    Read the numbers with care

    Benchmarks measure narrow tasks under one set of conditions, and results move quickly as models and agent tools change. Gaps of a few points are often within the margin of error. A model that ranks first here may not be the best on your own documents, processes or data. List prices change and some are introductory; open-weight prices depend on the host. Several well-known boards are not used to rank: SWE-bench, SWE-Bench Pro, OSWorld, tau-bench, BFCL and Aider have results for few or none of the models listed here, and METR's time-horizon board is no longer updated.
